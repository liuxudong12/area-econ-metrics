## 二、今天最该搞懂的 5 个概念

### 概念 1：VO 是什么？为什么不让前端直接传实体？

**VO = View Object（也有人叫 DTO / Request）**，就是"专门用来接收请求参数的对象"。

你可能会想：`Region` 实体已经有 `regionCode`、`regionName` 这些字段了，直接用它接收不就行了？

**不行，这是安全问题。** 看 `Region` 实体的字段：

```java
private Long id;
private String regionCode;
private String regionName;
private String parentCode;
private Integer regionLevel;
private Integer sort;
private Integer deleted;        // ← 危险
private LocalDateTime createTime;  // ← 危险
private LocalDateTime updateTime;  // ← 危险
```

如果直接用实体接收，别有用心的人可以发这样的请求：

```json
{"regionCode":"999999","regionName":"假数据","deleted":0}
```

`deleted = 0` 意味着"这条数据是正常的"——**他能把一条已逻辑删除的数据"复活"**。
或者伪造 `createTime` 来污染统计。

用 `RegionSaveReqVO` 只暴露"允许用户填的字段"，这叫**参数白名单**。用户可以填的只有 5 个：
编码、名称、上级编码、层级、排序。**做不到的事，就没有入口。**

> **面试标准答法**："VO 的作用有三个：参数白名单防止越权字段注入、与数据库结构解耦、
> 承载校验规则。我们不会把实体直接暴露给前端。"

### 概念 2：`@Valid` —— 校验注解的"开关"

`RegionSaveReqVO` 上写满了 `@NotBlank`、`@NotNull`、`@Size`、`@Min`、`@Pattern`：

```java
@NotBlank(message = "区域编码不能为空")
@Size(max = 32, message = "区域编码长度不能超过 32 位")
@Pattern(regexp = "^[0-9A-Za-z]+$", message = "区域编码只能是数字或字母")
private String regionCode;
```

**但这些注解本身不会自动生效。** 必须在 Controller 参数上加 `@Valid`：

```java
public Result<Long> create(@Valid @RequestBody RegionSaveReqVO reqVO) {
```

`@Valid` 就是那个"开关"。加了它，Spring 才会在方法执行**之前**去读那些注解；
不加，**所有校验注解全是摆设**（而且不报错，你根本发现不了）。

校验失败时抛 `MethodArgumentNotValidException`，被全局异常处理器接住，转成：

```json
{"code":400,"message":"regionLevel: 层级不能为空；regionName: 区域名称不能为空"}
```

**注意它把所有错误一次性返回**，而不是"改一个报下一个"——这才好用。

> ⚠️ 记住一个区别：`@Valid`（jakarta 标准）和 `@Validated`（Spring 的）都能用。
> `@Validated` 多了"分组"能力（同一个 VO 在新增和修改时用不同规则），
> 并且能加在类上以支持 `@RequestParam` 的校验。**面试可能问到，知道就行。**

### 概念 3：全局异常处理器 —— 让异常也有统一格式

**没有它会发生什么？** 你在 Service 里 `throw new BizException("区域编码已存在")`，
Spring 默认会返回 HTTP 500 + 一大段 Java 堆栈。三个问题：

1. **前端拿到的格式和正常响应完全不同**——正常是 `{code,message,data}`，出错是堆栈文本，没法统一解析；
2. **堆栈里会暴露类名、SQL、表名、文件路径**——等于给攻击者送情报；
3. **用户看到 "500 Internal Server Error"**，不知道自己哪里做错了。

`@RestControllerAdvice` 相当于**给所有 Controller 套了一层 try-catch**，
任何异常都会先来到这里，由匹配的 `@ExceptionHandler` 处理。

它按**就近原则**分流：

| 异常类型 | 谁来处理 | 返回给前端 | 日志级别 |
|---|---|---|---|
| `BizException` | `handleBizException` | **原始 message**（可以给用户看） | `warn` |
| `MethodArgumentNotValidException` | `handleMethodArgumentNotValid` | 字段级提示 | `warn` |
| `BindException` | `handleBindException` | 字段级提示 | `warn` |
| 其他所有异常 | `handleException` | **只返回统一话术**，绝不暴露细节 | `error` |

**两条铁律**（这两条比代码本身重要）：

- **兜底处理器里必须 `log.error("...", e)` 打完整堆栈。** 因为返回给用户的只是一句空话，
  真正的排查线索只存在于日志里。**忘了打，线上就瞎了。**
- **绝不能把 `e.getMessage()` 直接返回给前端。** 那可能是
  `Table 'area_econ.xxx' doesn't exist` 这种把库表结构都交代出去的话。

### 概念 4：RESTful 路径设计 + 一个必须知道的坑

```
查列表   GET     /api/region/list
查分页   GET     /api/region/page
查单条   GET     /api/region/{code}
新增     POST    /api/region
修改     PUT     /api/region
删除     DELETE  /api/region/{id}
```

同一路径 `/api/region` 挂了 POST 和 PUT，靠 **HTTP 方法**区分，不会冲突。
路径表示"资源"，方法表示"动作"。

> ### ⚠️ 坑：POST 和 PUT 的"重试语义"不同
>
> - **POST 不幂等**：同样的请求发两次，会**新增两条**数据；
> - **PUT 幂等**：同样的请求发两次，结果**一样**（都是"改成这个值"）。
>
> 所以"新增"必须用 POST，"按 id 整体覆盖更新"用 PUT。
> **面试问"幂等"时，这就是最基础的落点。**（第 11 天做异步导入时，你会真正用到幂等。）

### 概念 5：为什么新增要"先查再插"，不是多此一举吗？

看 `createRegion` 里的写法：

```java
long exists = lambdaQuery().eq(Region::getRegionCode, reqVO.getRegionCode()).count();
if (exists > 0) {
    throw new BizException("区域编码已存在：" + reqVO.getRegionCode());
}
```

数据库上明明已经有 `uk_region_code` 唯一索引了，为什么还要查一次？

**因为唯一索引抛的是 `DuplicateKeyException`**，message 是一长串英文 SQL 报错，
用户根本看不懂，而且它会被兜底处理器归类成"系统异常"（`error` 日志）。

**这是双保险写法：**
- **业务校验**（先查一次）→ 给用户**人话提示**；
- **数据库约束**（唯一索引）→ 做**最后防线**，防止并发下两个请求同时通过校验。

> **面试追问**："先查再插，并发下不还是会重复吗？"
> 答："会。所以真正兜底的是数据库唯一索引，捕获 `DuplicateKeyException` 再转成友好提示。
> 前面的 check 只是为了在 99% 的正常情况下给出更好的提示。"

## 三、三个写操作的核心代码

### 新增

```java
@Override
@Transactional(rollbackFor = Exception.class)
public Long createRegion(RegionSaveReqVO reqVO) {
    long exists = lambdaQuery().eq(Region::getRegionCode, reqVO.getRegionCode()).count();
    if (exists > 0) {
        throw new BizException("区域编码已存在：" + reqVO.getRegionCode());
    }

    Region region = new Region();
    BeanUtils.copyProperties(reqVO, region);   // VO → 实体，按同名属性复制
    region.setId(null);                        // 新增必须清空 id，否则破坏自增
    if (region.getSort() == null) {
        region.setSort(0);                     // 表里 sort 是 NOT NULL
    }
    save(region);
    return region.getId();                     // 自增 id 会被回填到对象里
}
```

**两个细节**：
- `region.setId(null)` —— 如果 VO 里带了 id，MyBatis-Plus 会以为你要指定主键，自增就失效了；
- `return region.getId()` —— `save()` 执行完，数据库生成的自增 id 会**回填**到对象上
  （靠 `@TableId(type = IdType.AUTO)`）。**这就是 `IdType` 那个注解的实际作用。**

### 修改

```java
Region old = getById(reqVO.getId());
if (old == null) {
    throw new BizException("区域不存在：" + reqVO.getId());
}

if (!old.getRegionCode().equals(reqVO.getRegionCode())) {
    long exists = lambdaQuery()
            .eq(Region::getRegionCode, reqVO.getRegionCode())
            .ne(Region::getId, reqVO.getId())      // ← 关键：排除自己
            .count();
    if (exists > 0) {
        throw new BizException("区域编码已被占用：" + reqVO.getRegionCode());
    }
}
```

`.ne(Region::getId, reqVO.getId())` 这一句**必须有**。不加的话，
"改一条记录的其他字段但编码不变"也会查到自己，直接报"编码已被占用"。

### 删除

```java
removeById(id);     // 因为实体上有 @TableLogic，实际执行 UPDATE ... SET deleted = 1
```

### 加分验收：去控制台看 SQL

访问上面这些接口时，控制台会打印真实执行的 SQL。**重点看这三条**：

```sql
-- 新增
INSERT INTO dim_region ( region_code, region_name, parent_code, region_level, sort ) VALUES ( ?, ?, ?, ?, ? )

-- 修改（注意末尾的 AND deleted=0）
UPDATE dim_region SET region_code=?, region_name=?, ... WHERE id=? AND deleted=0

-- 删除（注意它根本不是 DELETE！）
UPDATE dim_region SET deleted=1 WHERE id=? AND deleted=0
```

**第三条最值得盯三秒**：你调的是 `removeById`，执行的却是 `UPDATE`。
**这就是 `@TableLogic` 在起作用，你一行代码都没写。**

## 五、可能遇到的报错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 校验注解完全不生效，脏数据插进去了 | Controller 参数上漏了 `@Valid` | 补上 `@Valid`，**这是最常见的一个** |
| 返回一大堆 Java 堆栈而不是 JSON | `GlobalExceptionHandler` 没被扫描到 | 确认它在 `com.liuxudong.areaecon` 及子包下、有 `@RestControllerAdvice` |
| `MethodArgumentNotValidException` 没接住 | 只写了 `BindException` 处理器且版本不兼容 | 两个都写（我们代码里就是两个都写了） |
| `Cannot deserialize value of type ...` | body 里字段类型不对（比如 `"regionLevel":"二"`） | 这是 JSON 解析失败，属 `HttpMessageNotReadableException`，可以再加一个处理器 |
| 新增时插进去两条一样的 | POST 重试了，POST 本身不幂等 | 前端做防抖 + 后端靠唯一索引兜底 |
| `Field 'xxx' doesn't have a default value` | 表里 NOT NULL 又没默认值，实体里也没赋值 | 给字段补默认值，或表加 DEFAULT |
| 修改完发现别的字段被清空了 | `updateById` 只更新非 null 字段，你传了 null 想清空 | 要清空得用 `UpdateWrapper` 显式 `set(null)` |
