# 区域经济运行指标服务

> 独立开发的个人项目 · 用于秋招简历 · 代码全部自己写，可公开

---

## 一句话定位

参考企业级数据仓项目的建模思路，**从零独立实现**一个「区域 + 周期 + 指标编码」的统一指标管理服务，
支持多条件查询、大屏聚合、缓存加速与 Excel 异步批量导入。

---

## 为什么做这个项目

你要在简历上保留的三个技术亮点（索引优化 / 大屏缓存提速 / 异步重试幂等），
在实习项目里你没法光明正大地说是自己做的。**这个项目就是它们的容器。**

在这里，这三件事你可以完整地、真实地各做一遍：

| 你想写的 | 这个项目里怎么变成真的 |
|---|---|
| 响应时间下降 X% | 先**故意不建索引** → 造 10 万行数据 → 测出慢查询 → `EXPLAIN` 分析 → 补索引 → 重测 |
| 大屏接口 X ms → Y ms | 给聚合接口加 Redis 缓存，前后耗时自己打点对比 |
| 异步 + 重试 + 幂等 | 把 Excel 批量导入改成异步任务，自己设计幂等键与重试策略 |

做完之后，这三句话**完全是真的**——有代码、有 commit、有实测数字、能扛住任何追问。

## 14 天任务清单

每天做完打勾，**并且当天必须 git commit**（commit 记录就是你的证据）。

### 第 1–2 天 · 搭骨架
- [ ] 建 Maven 项目，引入依赖（Web / MyBatis-Plus / MySQL Driver / Redis / EasyExcel / Lombok）
- [ ] 建库建表：执行 `sql/schema.sql`
- [ ] 配置 `application.yml`（数据源、MyBatis-Plus、Redis）
- [ ] 写一个 `/ping` 接口，确认服务能起来
- [ ] 建立实体类 + Mapper + Service + Controller 分层

### 第 3–5 天 · CRUD 与 Excel
- [ ] 区域管理：CRUD + 分页 + 按名称模糊查询
- [ ] 指标管理：CRUD + 按分类筛选 + 树形结构返回
- [ ] 指标值管理：新增/修改/删除/分页 + **按区域+指标+周期精确查询**
- [ ] EasyExcel 导入：解析 Excel → 校验 → 批量入库（先做**同步版本**）
- [ ] EasyExcel 导出：按查询条件导出，**导出字段必须与列表接口一致**

### 第 6–8 天 · 聚合与大屏 + 慢查询优化
- [ ] 大屏聚合接口：某区域下按周期类型（年/季/月）聚合指标值
- [ ] 缺失周期沿用上期值补齐
- [ ] 写造数据脚本，往 `fact_indicator_value` 灌 **10 万行以上**
- [ ] **记录优化前耗时**：用 `EXPLAIN` 看大屏聚合查询的执行计划，截图保存（`type`、`key`、`rows`）
- [ ] **加索引**，重写 SQL，再次 `EXPLAIN` 并记录耗时
- [ ] 把前后对比数字写进 `docs/02` 的记录区

### 第 9–10 天 · Redis 缓存
- [ ] 给大屏聚合接口加缓存：先查缓存 → miss 查库并回填 → TTL 10 分钟
- [ ] 数据更新/删除时**主动删除**相关缓存
- [ ] 用日志打点记录缓存命中/未命中的耗时，**测出缓存前后的差距**
- [ ] 把数字写进 `docs/02` 的记录区

### 第 11–12 天 · 异步导入 + 重试 + 幂等
- [ ] 新建 `async_task` 任务表（已在 schema.sql 里）
- [ ] Excel 导入改为异步：上传 → 算文件 MD5 → 落任务表 → 提交线程池 → 立即返回任务 ID
- [ ] 幂等：同一份文件重复提交，直接返回已有任务，不重复执行
- [ ] 重试：失败后指数退避重试（1s / 2s / 4s），最多 3 次，超过标记 FAILED
- [ ] 提供任务状态查询接口
- [ ] 补单元测试：覆盖重试逻辑与幂等逻辑

### 第 13 天 · 收尾
- [ ] 写 README（本文件已给你框架，补充「我在这个项目里做了什么」一节）
- [ ] 整理代码：统一异常处理、统一返回体、参数校验
- [ ] 推到自己的 GitHub（**公开仓库**，因为代码是你自己写的）

### 第 14 天 · 简历与面试
- [ ] 把项目写进简历（第 03 节有模板）
- [ ] 按 `docs/03-面试问答提纲.md` 逐条自测，答不上来的当天补掉
- [ ] 找人模拟面试一次

## 每日自检（很重要，别跳过）

每天结束前问自己这三句：

1. **今天我写的每一行代码，我能解释它为什么这么写吗？**
2. **如果面试官问「为什么不用另一种方案」，我答得上来吗？**
3. **今天的 commit message 说清楚我做了什么吗？**（面试官会看）

> 用 AI 帮你写代码没问题——**这是 2026 年最正常的工作方式**。
> 但你必须做到：AI 给的每一段，你都能讲清设计取舍。做不到就删掉重写。
